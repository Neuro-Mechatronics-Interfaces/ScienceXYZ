# RHD2132 SPI-Master Peripheral — Implementation Plan (plan only)

Status: **plan only, no code written.** Supersedes the "config-only physical
adapter" framing in `docs/peripheral-sources-plan.md` for the case where we
author our own RHD2132 gateware. Written 2026-08-26.

This document is the durable record of a decision that has been revised several
times. Read the "Settled facts" section first; it is the ground truth the rest
of the plan is built on.

## Settled facts (do not re-litigate)

1. **The probe front end is a physical Intan RHD2132** — a 32-channel biopotential
   ADC/amplifier chip driven over SPI. Confirmed by the Science representative and
   by the earlier bench `info` (the adapter previously enumerated as
   `IntanRHD2132`, ID 200, type `kBroadbandSource`). It is not the NYX-512, and it
   is not an FPGA. The NYX-512 line of reasoning is dropped.

2. **The FPGA that must drive the RHD2132 is the Lattice device on the SciFi-2
   headstage.** Radiant 2026.1 is installed; a node-locked license is configured
   (`LATTICE_LICENSE_FILE = C:\lscc\radiant\2026.1\license\license.dat`). Note the
   gateware `peripheral.yaml` pins `build.radiant_version: '2026.1'`.

3. **The adapter enumerates again (as of 2026-08-26).** `synapsectl -u
   192.168.100.157 info` lists `IntanRHD2132` (ID 200, `kBroadbandSource`, Intan
   Technologies) alongside the virtual peripherals (1000, 1001). The 2026-08-24
   non-enumeration was a transient link/electrical-level issue (adapter, cable, or
   port; software exonerated per `MISTAKES.md`), now cleared — ID 200 was never
   destroyed by our deploys. **Consequence: the stock config-only recording path is
   available today** (bind `peripheral_id: 200`; no custom gateware, no Radiant).
   That makes this SPI-master gateware effort **optional/long-term** — an effort to
   own the gateware (custom on-device processing, a peripheral we control at
   `0xF200`), not the only way to get data off the probe.

4. **80 MHz gateware clock; 20 kHz sample rate.** Science's docs state the RHD2132
   gateware "derives the sample period from a fixed 80 MHz clock" and the sample
   rate is "greater than 0 and at most 30000". We choose **20 kHz** for
   convenience (their stock uses 30 kHz). The adapter build profile
   `omnetics-32ch-adapter` therefore uses `CLK_FREQ_HZ = 80'000'000` — already set
   correctly in `axon_omnetics32ch_source_constants.h`.

5. **RHD2132 fixed electrical constants** (Science docs + Intan datasheet):
   - Amplifier gain fixed at **192 V/V**.
   - **1 LSB = 0.195 µV** at the input (16-bit two's-complement samples).
   - Low-cutoff corner 0.1–500 Hz; high-cutoff corner 100–20000 Hz; both must be
     set together (a config setting one and leaving the other empty is rejected).
   - On-chip impedance-check DAC; per-electrode (0–31); cannot run during
     recording; stimulation frequency ≥ 250 Hz.

## What exists today (the starting point)

The `m053m716/omnetics-32ch-adapter` branch of `vendor/axon-peripherals` (editable
per the AGENTS.md `m053m716/`-branch exception) contains a scaffold that is a
**renamed copy of the synthetic `axon_test_source`**. It compiles and streams
fake data; it does not touch real silicon. Concretely:

- `src/gateware/axon_omnetics32ch_source_peripheral.sv` — synthesises LFP + spikes
  + noise in the FPGA; module is still named `axon_test_source_peripheral_top`;
  **no SPI, no RHD register logic, no MISO capture**.
- `src/gateware/omnetics-32ch-adapter/src/omnetics32ch_top.sv` — an
  AUTO-GENERATED copy of the **NeRV512U** top (`module nerv_top`, 60 MHz `clki`,
  USB3, wired to `axon_test_source_peripheral_top` at id `0xF001`). It has **no
  Omnetics/SPI pins** and does not reference the omnetics peripheral by name. The
  profile scaffold was generated by copying nerv512u and only partly renamed.
- `peripheral.yaml` — `io: []` (no physical pins declared), `dev_peripheral_id:
  0xf200`, opcodes CONFIGURE 0x52 / START 0x54 / STOP 0x55 / DATA_FRAME 0x56.
- `src/driver/axon_omnetics32ch_source_*` — driver copy with `MAX_CHANNEL_COUNT
  = 32`, `MAX_SAMPLE_RATE = 30000`, `MAX_BIT_WIDTH = 16`, `MAX_GAIN = 1`, but
  `get_lsb` returns 1.0, gain unmodeled, `get_impedance` returns `INVALID_STATE`,
  `validate_ephys_config` accepts anything. All placeholder.

**Implication:** turning this into a real RHD2132 interface is a from-scratch
gateware design plus a driver rewrite, not a tweak.

## Reference bodies (cite these, don't reinvent)

1. **SDK ABI (reverse-engineered from `sdk/libscifi-peripheral-sdk.so.0.2.0`).**
   Transport is ZeroMQ PUB/SUB; the plugin-facing `send_packet` /
   `subscribe_persistent` / `drain_rx` wrap `axon::send_axon_packet` /
   `subscribe_to_axon_messages`. Packet = magic `0xC0FFEE00` + 16-bit header +
   `(opcode<<16 | len)` + payload + CRC32, max payload 0xFE4 bytes. See the
   `scifi-peripheral-sdk-headers-in-docker` memory for full ABI notes. This layer
   is unchanged by this work — we keep the CONFIGURE/START/STOP/DATA_FRAME frame
   contract; only the peripheral's behaviour behind it changes.

2. **The SDK's own reference driver** `src/driver/axon_test_source_peripheral.cpp`
   — the correct shape for `start_recording_impl` (configure → subscribe →
   drain → start), `parse_frame_payload`, `configure_channels` (sets
   `ChannelRange` type ELECTRODE), and registration via
   `SCIFI_REGISTER_PERIPHERAL`. Our driver keeps this control flow.

3. **Intan RHD FPGA firmware** `third_party/intan/firmware/rhd/xem7310_common/main.v`
   (3997 lines) — the authoritative RHD SPI polling engine. It is the exhaustive
   8-port (A–H), multi-headstage version; we need a **single-port, single-chip**
   subset. Key structures to port down (with line anchors):
   - Ports per SPI bus: `CS_b`, `SCLK`, `MOSI`, `MISO` (main.v:60–114).
   - `dataclk` = "2800 × per-channel amplifier sampling rate" (main.v:185). Each
     channel is one 16-bit SPI transaction; the FSM walks `channel` 0..33 (32
     amplifiers + 3 aux command slots) once per sample period (main.v:232).
   - 16-bit MOSI command words shifted MSB-first: `MOSI <= MOSI_cmd[15]` then the
     4-substate-per-bit SCLK engine `ms_clk1_a..d` … `ms_clk16_d`
     (main.v:1281–~1990). Substates give SCLK setup/rise/hold/fall timing.
   - **MISO pipeline latency:** `channel_MISO <= 33` with the comment
     "accounting for 2-cycle pipeline in RHD2000 SPI interface" (main.v:1173). The
     RHD returns each CONVERT result **two commands later**; capturing MISO in the
     same transaction that issued CONVERT reads the wrong channel. This is the
     single most bug-prone detail; the design must model it explicitly.
   - Register writes / calibration are issued as the **aux commands** (channels
     32–34) from host-loaded command-RAM banks (`aux_cmd_bank_*`, main.v:1192–1215).

## RHD2132 command + register model (what the gateware must emit)

RHD2000-family SPI commands are 16-bit, MSB-first, two per SCLK frame of 16 bits.
The four we need:

| Command  | Encoding (bits [15:14]) | Use |
| --- | --- | --- |
| CONVERT(ch) | `10` + 6-bit channel + flags | Sample amplifier channel `ch` (0–31). One per channel per sample period. |
| READ(reg)   | `11` + 6-bit reg address | Read a config register (used for the ROM/ID handshake at init). |
| WRITE(reg,data) | `10`… no — `WRITE` is `10`? see note | Write a config register. Used only at init. |
| CALIBRATE / CLEAR | dedicated opcodes | ADC self-calibration after power-up; CLEAR aborts it. |

> Note: the exact opcode bit patterns must be taken from the Intan RHD2000
> datasheet / `main.v` command-composer, not memorised here — the table above is
> the intent, and the plan step below pins the exact bits from the reference
> before any RTL is written. Do not hardcode a guessed opcode.

**Init register set (RHD2132 registers 0–17), issued once at start-of-recording
as WRITE aux commands, then an ADC CALIBRATE:**

- R0–R3: ADC configuration, bias, MUX bias, ADC buffer bias, amplifier
  fast-settle / power.
- R4–R5: on-chip DSP high-pass (offset removal) enable + cutoff `k`.
- R6–R7: impedance-check DAC (only touched for `get_impedance`).
- R8–R13: analog bandwidth — RH1/RH2 (upper cutoff) and RL (lower cutoff)
  register pairs. These encode the 100–20000 Hz / 0.1–500 Hz corners; the driver's
  `hp_corner`/`lp_corner` map to these values via the Intan bandwidth tables.
- R14–R17: individual amplifier power-up bitmask (which of the 32 channels are on).

The concrete register values come from the Intan RHD2000 datasheet bandwidth
tables and are the same ones Intan-RHX computes in its C engine (see
`third_party/intan` `Engine/`/`libraries/` for the reference implementation of the
bandwidth→register math — reuse those formulas rather than deriving new ones).

## Design — gateware

Target: a **single-port RHD2132 SPI master** peripheral module replacing the
synthetic generator, preserving the SDK frame contract so the driver and transport
are unchanged.

1. **Module + ports.** New `axon_omnetics32ch_source_peripheral.sv` exposing the
   SDK contract ports (`clk`, `rst`, `periph_addr`, `rx_axis.secondary`,
   `tx_axis.main`) **plus** the physical RHD pins `spi_cs_n`, `spi_sclk`,
   `spi_mosi`, `spi_miso`. Keep the CONFIGURE/START/STOP RX decoder and the
   DATA_FRAME TX framer from the current scaffold (they already match the driver);
   replace only the data-source guts.

2. **SPI clocking from 80 MHz.** Derive SCLK and the per-channel pacing from the
   80 MHz `clk`. RHD2132 SCLK max is 24 MHz+; choose a conservative divisor (e.g.
   SCLK = clk/4 = 20 MHz) and verify against the datasheet's SCLK/CS timing.
   Per-channel budget: 16 SCLK bits + CS framing. One sample period must fit 35
   transactions (32 CONVERT + 3 aux). Sanity: at 20 kHz, one sample period = 4000
   `clk` ticks (80 MHz / 20 kHz); 35 transactions × ~(16·divisor + framing) must be
   ≤ 4000 ticks — this bounds the SCLK divisor and is a hard constraint to check in
   the plan-to-RTL step, not assume.

3. **Command sequencer.** A `channel` counter 0..34 like `main.v`. For channels
   0–31 issue CONVERT(ch); for 32–34 issue the queued aux command (register writes
   during init, dummy READ/ID during steady state). MOSI shifts MSB-first through
   the SCLK substate engine.

4. **MISO capture with the 2-transaction pipeline offset.** Shift MISO in on the
   correct SCLK edge; associate the captured 16-bit word with the channel issued
   **two transactions earlier** (`channel_MISO` model). Emit exactly the 32
   amplifier results per sample period into the DATA_FRAME payload, low 16 bits =
   signed sample, matching `parse_frame_payload`.

5. **Init + calibrate FSM.** On START_STREAM: run the register-write sequence
   (R0–R17), issue ADC CALIBRATE, wait the datasheet-specified settling, then begin
   the steady CONVERT loop. On STOP_STREAM: stop issuing CONVERT, optionally
   power-down amplifiers.

6. **Constraints + top wiring (the currently-missing adapter-specific work).**
   - Regenerate the `omnetics-32ch-adapter` top so it instantiates the real
     omnetics peripheral (not `axon_test_source_peripheral_top`) and exposes the
     SPI pins. The generated top is checksummed; use `axon-peripheral-sdk generate`
     / `--force` per the gateware README rather than hand-editing blindly.
   - Declare the SPI pins in `peripheral.yaml` `fpga.io[]` and add pin-location +
     I/O-standard constraints in the user region of `omnetics32ch_sdk.pdc`, and
     SCLK timing in `omnetics32ch_sdk.sdc`. **Pin numbers require the SciFi-2
     headstage schematic / adapter pinout from Science — this is a blocking input.**

## Design — driver (`src/driver/axon_omnetics32ch_source_*`)

Make the driver tell the truth about the RHD2132:

- `get_lsb()` → return **0.195f** (µV/LSB), not 1.0. This is what scales counts to
  microvolts downstream.
- Model the fixed **192 V/V** gain where the SDK expects gain (advertise via limits
  / config as appropriate; `MAX_GAIN` semantics to be confirmed against the SDK
  header — gain is fixed, not selectable).
- `configure_sample_rate()` → clamp to (0, 30000]; use 20 kHz default; the gateware
  `sample_period` is `CLK_FREQ_HZ / actual` = 4000 at 20 kHz (already computed in
  `start_recording_impl`).
- `validate_ephys_config()` → enforce the real contract: **both** hp and lp corners
  present; hp ∈ [0.1, 500] Hz; lp ∈ [100, 20000] Hz; bit_width == 16. Reject
  otherwise with a descriptive message (the SDK surfaces it at signal-chain start).
- `get_impedance()` → implement via the RHD impedance DAC path: reject if recording
  (return `INVALID_STATE`), else program R6–R7, drive the test frequency (≥ 250 Hz),
  CONVERT the electrode, and return magnitude/phase. Requires new aux-command +
  a small RX result path; may be phased in a second pass.
- Map `hp_corner`/`lp_corner` (passed into `start_recording_impl`) to the RHD RL/RH
  register values and deliver them to the gateware — either extend CONFIGURE's
  payload or add a WRITE-registers opcode. **Frame-contract change:** if we extend
  CONFIGURE, bump the opcode payload contract in both `constants.h`,
  `peripheral.yaml`, and the gateware RX decoder together.
- Keep `to_proto()` name/vendor; keep `SCIFI_REGISTER_PERIPHERAL(... 0xF200)`.

## Design — tests

- Extend the cocotb bench `test/tb/test_axon_omnetics32ch_source.py`. Because the
  suite compiles only the peripheral RTL + `axi4_stream_interface` (never a top),
  add a **behavioural RHD2132 SPI-slave model** in the testbench: it answers
  CONVERT with a known per-channel ramp/sine and honours the 2-transaction MISO
  latency, so the test asserts the DATA_FRAME payload matches the model including
  the pipeline offset. Assertions count clock cycles (the existing convention), so
  they hold at either 40/80 MHz.
- Add a register-init assertion: on START_STREAM the DUT issues the R0–R17 WRITE
  sequence + CALIBRATE before the first CONVERT.

## Blocking inputs (must resolve before/within each stage)

1. **Adapter must electrically enumerate again** (currently a link-level fault,
   escalated to Science). No gateware can be validated on hardware until this is
   fixed. Gateware/driver/testbench development can proceed against the SPI-slave
   sim model in the meantime.
2. **SciFi-2 headstage → RHD2132 SPI pin mapping** (CS/SCLK/MOSI/MISO pin
   locations + I/O standard) — needed for `.pdc`. From Science's schematic /
   adapter datasheet.
3. **Exact RHD2000 command opcode bit patterns and the R0–R17 init values /
   bandwidth tables** — pin from the Intan datasheet + `third_party/intan` C engine
   before writing RTL; do not guess.
4. **Confirm the SciFi target actually lets a user peripheral own the RHD SPI
   pins** on the internal fabric (the stock RHD2132 peripheral already uses them).
   If those pins are committed to Science's transport/stock peripheral, a
   user-authored SPI master may need the Via/devkit path instead of the SciFi
   internal fabric. This is the same "can a user peripheral claim these pins"
   question flagged in `docs/peripheral-sources-plan.md`.

## Recommended sequencing

1. Resolve adapter enumeration with Science (parallel; gates hardware bring-up).
2. Pin the RHD opcode/register facts from the datasheet + Intan reference (desk work).
3. Build the SPI-slave sim model + rewrite the peripheral RTL + cocotb tests
   (sim-only, no hardware, no license needed).
4. Rewrite the driver's electrical contract (LSB/gain/validate/rate).
5. Once pins are known: regenerate the adapter top, add `.pdc`/`.sdc`, build the
   bitstream under Radiant.
6. Deploy + bench bring-up against the (recovered) adapter.
